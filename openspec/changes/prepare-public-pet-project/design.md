## Context

Мотивация описана в proposal.md. Проверены общий Prisma adapter, auth cookie/JWT flow, AI router, payment router и действующие capability-specs. Работа продолжается в prepare-public-pet-project. Платёжный и auth контуры имеют database-free тесты. Пользователь сообщил об отсутствии backup Timeweb и выбрал новую пустую базу без тестовых данных. Существующий Render вручную переключён на master, автодеплой выключен; внешнее размещение агентом не выполнялось.

## Goals / Non-Goals

**Goals:** воспроизводимые исправления выявленных рисков и подготовка публичного проекта. Каждая находка получает статус: исправлена, проверена и не подтверждена, либо ожидает конкретное внешнее действие.

**Non-Goals:** автоматическая смена видимости, внешних secrets, DNS, восстановление без backup, несогласованное удаление истории, force push и изменение лицензии. Удалять интеграцию оплаты целиком не требуется; её исходники и тесты ценны для портфолио. Локальная очистка согласованных исторических материалов разрешена только в изолированной копии после backup.

## Decisions

1. TLS: выделить чистый разбор DB-конфигурации, сохранить единственный pool/client. Для удалённой базы проверять CA и hostname; поддержать явно выбранный локальный режим. Удалить конфликтующие ssl query-параметры перед передачей конфигурации pg, чтобы URL не переопределял проверку сертификата. Опциональный CA поступает через серверную конфигурацию, без insecure fallback. Альтернатива `rejectUnauthorized: false` отвергнута.
2. AI: `/analyze` использует существующие reserve/release helpers, как остальные AI routes. Добавить burst limit для платных AI-сценариев. Сохранить graceful fallback и контроль пользователя.
3. Auth: добавить общую IP-корзину login, сохранить текущую IP/email-корзину; перейти на async bcrypt. Использовать ограниченный lifetime и явный HS256. Для отзыва добавить таблицу хешированных fingerprints завершённых токенов с expiresAt и проверкой middleware. Это сохраняет действующие JWT до logout и не хранит сырые токены. In-memory denylist отвергнут: Render теряет его при рестарте. Миграция только локально подготовлена.
4. Enumeration: в портфолио-режиме отключить новую регистрацию общим серверным флагом до поиска email и создания аккаунта, включая web и Telegram Mini App. Возвращать одинаковый отказ независимо от существования email; frontend объясняет ограничение по-русски. Сохранить вход и привязку существующих аккаунтов и браузерный гостевой режим. Legacy registration при явном включении сохраняет остаточный риск enumeration; полноценный email-verification flow не добавлять.
5. Payments: проверить format/length id, искать локальную Payment до provider fetch, установить timeout и webhook IP limiter. Проверенную активацию выполнять через условный updateMany paid=false и изменение пользователя в одной interactive transaction. Обработать конкурентные succeeded/canceled и retries. Checkout confirmation URL принимать только HTTPS. Поддержку живой оплаты выключать серверным и frontend flag лишь после выбора владельца; default публичного примера выключен.
6. HTTP: сохранить CSRF Origin/Referer защиту, валидировать точные origins, документировать trust proxy согласно Render/Vercel topology. Добавить безопасные JSON ошибки, отключить x-powered-by. Перевести CSP frontend из report-only в блокирующий Content-Security-Policy после проверки реального заголовка и браузерных сценариев: гостевой режим, auth, Telegram embedding, PWA и фоновые blob URL. Добавить отрицательную проверку блокировки недоверенного inline script; не применять DENY к Mini App. Design showcase доступен только в dev/catalog build.
7. Client logs: заменить сырые console errors безопасными кодами без payload. Backend path logging использовать шаблон маршрута вместо произвольного пути. Расширить ignores для ключей, backup, выгрузок, сохранив migrations и допустимые fixtures.
8. ai-proxy: до решения об удалении сохранить код и усилить timeout/error/rate-limit/constant-time проверки, проверить его локально. Нельзя оставлять medium risk только потому, что сервис сейчас выключен.
9. Документы: составить file-level manifest без персональных значений. Внутренние документы перемещать в приватную копию вне репозитория только по согласованному списку. README содержит продукт, реальные инженерные задачи, безопасный запуск, тесты и maintenance-статус. All Rights Reserved остаётся до отдельного выбора. Исторические specs не редактировать попутно.
10. Размещение: использовать существующий frontend rewrite `/api` для same-origin cookie через Vercel, переиспользовать Render web service на master с выключенным автодеплоем, базу разместить Neon. Удалить ранее подготовленный demo seed и инструкции его запуска. Новая база содержит только схему, без автоматически созданных аккаунтов, задач и платежей; гостевые данные остаются локально в браузере. Database-free fixtures не являются данными PostgreSQL и сохраняются. Render worker прекращает работать во время сна: своевременная фоновая обработка Telegram на бесплатном плане не гарантируется. Не использовать искусственный keep-alive для обхода тарифа.
11. Git: перед очисткой проверить приватный backup всех доступных refs и отдельно сохранить незакоммиченные изменения; bundle их не содержит. Переписывать только изолированную копию: согласованные внутренние документы, старые личные реквизиты и подтверждённые email владельца на GitHub noreply. Чужие авторские metadata не менять. Проверить все refs очищенной копии и отдельно сообщить, что исходный checkout и GitHub всё ещё содержат старую историю. Подмена исходного checkout, push и force push требуют отдельного решения.

## Risks / Trade-offs

Метрика удаляется по подтверждению владельца: script, счётчик, env-настройка и баннер.
Совместимые no-op функции событий сохраняют существующие call sites без передачи или
хранения tracking state и без изменения LandingPage. Технические auth cookies сохраняются.
Локальный Playwright preview разрешает HTTP mock API только через отдельный test-only flag;
production Vercel CSP остаётся без этого исключения.

- Новая revoke-таблица → подготовить migration и SQL review; применение требует backup и согласования.
- Живая база недоступна → сначала выяснить восстановимость у Timeweb; не загружать backup в Git или переписку.
- Зарубежный хостинг и реальные пользователи → перенос личных данных требует отдельной оценки условий обработки; новая база остаётся пустой, синтетические данные также не создаются.
- CSP и cookies могут нарушить Telegram → отдельный browser smoke после нового размещения.
- Очистка текущих файлов не очищает историю → выполнять согласованный rewrite только в изолированной локальной копии с проверенным backup; удалённая история не меняется автоматически.
- Free hosting не покрывает AI расходы → явно указать ограничения, не обещать полностью бесплатную живую генерацию.

## Migration Plan

Продолжить implementation branch от проверенного dev. Выполнить исправления и локальные gates без записи тестовых данных в PostgreSQL. Повторить secret/dependency scan и очистить согласованную историю в изолированной копии после backup. Настроить hosting после отдельного разрешения и проверки нового пустого целевого подключения, применить согласованную схему без seed. Production migration остаётся под требованиями конституции к backup и согласованию; отсутствие Timeweb backup не разрешает изменять старую базу. Проверить health и браузерный guest flow; проверки с записью данных на внешней базе не выполнять без нового разрешения. DNS переключать после smoke. Перед Make public отдельно проверить очищенную историю и GitHub artifacts; удалённые refs не менять автоматически.
