# Feature Specification: Инструменты планирования задач

**Feature Branch**: `codex/task-filters-subtask-drafts`  
**Created**: 2026-09-04  
**Status**: Clarified  
**Input**: Продолжить автономное усиление продукта: добавить удобные фильтры задач и AI-разбиение задачи на редактируемые шаги без скрытого сохранения.

## Clarifications

### Session 2026-09-04

- Фильтры действуют только в текущем открытии экрана и сбрасываются явно или после новой сессии; пользовательские данные не сохраняются в отдельном хранилище.
- AI предлагает от 2 до 8 коротких шагов только после нажатия пользователя; один запрос расходует одну единицу существующего backend-лимита.
- Полученный список остаётся черновиком: пользователь может изменить, удалить или отменить его; данные меняются только после отдельного подтверждения.
- В форме новой задачи подтверждение добавляет шаги в локальную форму, а в существующей задаче — через действующий API подзадач с честным частичным результатом.

## User Scenarios & Testing

### User Story 1 — Быстро сузить список задач (Priority: P1)

Пользователь открывает дополнительные фильтры и сочетает срок, энергию, приоритет и категорию, видя число активных условий и возможность одним действием всё сбросить.

**Independent Test**: создать разнородные задачи и проверить каждую комбинацию, счётчик и сброс на desktop и mobile.

**Acceptance Scenarios**:

1. **Given** есть просроченные, сегодняшние, будущие задачи и задачи без даты, **When** выбран фильтр срока, **Then** остаётся только соответствующая группа.
2. **Given** выбраны несколько условий, **When** показан список, **Then** задача должна удовлетворять всем условиям одновременно.
3. **Given** активны фильтры, **When** пользователь нажимает «Сбросить», **Then** дополнительные условия очищаются, не меняя задачи, поиск, статус или сортировку.

### User Story 2 — Получить редактируемый черновик шагов (Priority: P1)

Пользователь нажимает «AI шаги» в форме задачи и получает небольшой реалистичный список, который можно проверить и отредактировать до сохранения.

**Independent Test**: запросить шаги, изменить и удалить пункты, затем отменить; ни одна задача или подзадача не меняется.

**Acceptance Scenarios**:

1. **Given** у задачи есть заголовок, **When** пользователь явно запрашивает AI-шаги, **Then** backend проверяет авторизацию и лимит и возвращает валидированный список из 2–8 пунктов.
2. **Given** черновик получен, **When** пользователь редактирует или удаляет пункты, **Then** изменения остаются локальными до подтверждения.
3. **Given** пользователь закрывает или отменяет черновик, **Then** существующие и создаваемые данные не меняются.

### User Story 3 — Явно применить выбранные шаги (Priority: P2)

Пользователь подтверждает проверенный черновик. В новой задаче шаги добавляются в форму, а в существующей — создаются через текущий механизм подзадач.

**Independent Test**: подтвердить изменённый черновик в обеих формах и проверить точный состав; смоделировать частичную ошибку существующей задачи.

**Acceptance Scenarios**:

1. **Given** открыта новая задача, **When** подтверждён черновик, **Then** шаги добавляются в локальный список, но задача сохраняется только общей кнопкой формы.
2. **Given** редактируется существующая задача, **When** подтверждён черновик, **Then** создаются только непустые уникальные шаги.
3. **Given** часть запросов создания не удалась, **When** применение завершено, **Then** успешные шаги видны, неприменённые остаются в черновике и показано понятное сообщение.

### Edge Cases

Пустой заголовок; лимит исчерпан; provider недоступен; невалидный ответ; повторный клик; дубли с существующими шагами; пустой черновик после редактирования; 320–430 px; смена статуса при активных фильтрах; категории с пробелами. Пользовательский текст не попадает в новые логи и продуктовые события.

## Requirements

### Functional Requirements

- **FR-001**: Дополнительные фильтры поддерживают срок, энергию, приоритет и категорию и комбинируются логическим «И».
- **FR-002**: Интерфейс показывает количество активных дополнительных условий и отдельный сброс.
- **FR-003**: Фильтры не меняют порядок исходных задач и работают совместно с текущими статусом, поиском и сортировкой.
- **FR-004**: Фильтры доступны с клавиатуры и помещаются на desktop и ширине 320–430 px.
- **FR-005**: Запрос AI-шагов требует непустой заголовок и явное действие пользователя.
- **FR-006**: Авторизация, AI-лимит и вызов провайдера выполняются на backend через существующие механизмы.
- **FR-007**: Request/response/error валидируются общими контрактами; ответ содержит 2–8 непустых шагов не длиннее 160 символов.
- **FR-008**: AI-ответ не создаёт и не изменяет задачи или подзадачи до отдельного подтверждения.
- **FR-009**: Черновик позволяет редактировать и удалять шаги, повторить запрос и отменить без изменений данных.
- **FR-010**: Подтверждение в create-flow добавляет шаги только в локальную форму; окончательное сохранение остаётся отдельным действием.
- **FR-011**: Подтверждение в edit-flow переиспользует существующее создание подзадач, исключает пустые и нечувствительные к регистру дубли.
- **FR-012**: Частичная ошибка edit-flow сохраняет успешные результаты и оставляет неуспешные шаги для повтора.
- **FR-013**: Новые логи и продуктовые события не содержат названий задач, подзадач, prompt или provider response.
- **FR-014**: Изменение не требует новой таблицы, миграции, env, отдельного AI-клиента или нового Prisma instance.

### Key Entities

- **Набор фильтров**: локальные значения срока, энергии, приоритета и категории.
- **Черновик шагов**: временный массив редактируемых строк и состояние загрузки/ошибки/применения.
- **Результат применения**: созданные и неприменённые шаги без пользовательского текста в телеметрии.

## Success Criteria

- **SC-001**: Автотесты подтверждают точную выдачу для одиночных и комбинированных фильтров и полный сброс.
- **SC-002**: До явного подтверждения во всех automated scenarios выполняется ноль task/subtask mutations.
- **SC-003**: Каждый уникальный подтверждённый шаг существующей задачи создаётся не более одного раза.
- **SC-004**: Невалидный provider response никогда не попадает в форму и даёт понятное русское сообщение.
- **SC-005**: Новый flow проходит contract/backend/component и desktop/mobile проверки, а typecheck, lint, unit tests и build успешны.

## Assumptions

Первый slice не сохраняет наборы фильтров и не добавляет календарную фильтрацию по диапазону. AI не меняет основную задачу и не пересчитывает её поля. Переводы, полноценный редизайн, календарь, БД/env/production/push и `LandingPage.tsx` находятся вне scope.
