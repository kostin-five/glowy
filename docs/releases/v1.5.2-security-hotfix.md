# Релиз v1.5.2 - Security Hotfix

## Обзор
Этот релиз направлен на усиление безопасности приложения Glowy перед коммерческим запуском v2.0.0. Включены защиты от CSRF, брутфорс-атак, перебора пользователей, а также улучшена валидация на стороне сервера.

## Изменения

### Backend
- **Защита от CSRF**: Добавлен middleware для проверки заголовков `Origin` и `Referer` для небезопасных HTTP-методов (`POST`, `PUT`, `PATCH`, `DELETE`). Используется строгое соответствие разрешенным origin.
- **Ограничение частоты запросов (Rate Limiting)**: 
  - Внедрены строгие лимиты для `/api/auth/login` (5 попыток за 15 мин) и `/api/auth/register` (10 регистраций в час).
  - Для входа используется комбинированный ключ IP + Email для защиты от распределенных атак на аккаунт.
- **Безопасные ошибки авторизации**: Унифицированы сообщения об ошибках для входа и регистрации, чтобы предотвратить перебор email-адресов.
  - Вход: всегда возвращается «Неверный email или пароль».
  - Регистрация: возвращается безопасное сообщение при существовании пользователя или общая ошибка.
- **Защита Dev-окружения**: Добавлен заголовок `X-Robots-Tag: noindex, nofollow` для домена `dev.glowy-ai.ru`.
- **Безопасность эндпоинтов**: Эндпоинт `/api/chat` теперь требует авторизации.
- **Валидация**: Добавлена серверная валидация через `express-validator` для задач, подзадач и прогресса пользователя. Улучшена проверка ID в маршрутах. Валидация дат теперь поддерживает форматы `YYYY-MM-DD` и `DD.MM.YYYY` для совместимости с задачами, созданными через AI Hub.
- **CORS**: В production разрешены только `https://glowy-ai.ru` и `https://www.glowy-ai.ru`. Локальные адреса разрешены только в режиме разработки.

### Frontend
- **Конфигурация API**: Удален автоматический fallback на localhost в production. Переменная `VITE_API_URL` теперь обязательна.

## Примечания для развертывания
- При использовании Cloudflare или Nginx убедитесь, что `trust proxy` настроен корректно для правильной работы Rate Limiting по IP.
- Для dev-версии фронтенда может потребоваться дополнительная настройка `noindex` на уровне хостинга статики.
