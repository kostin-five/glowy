# Feature Specification: Независимый от Telegram запуск сайта

**Feature Branch**: `codex/nonblocking-telegram-sdk`
**Created**: 2026-09-03
**Status**: Specified
**Input**: Выполнить следующий roadmap fix: сайт не зависает при недоступном Telegram SDK.

## User Scenarios & Testing

### User Story 1 — Обычный сайт работает независимо (Priority: P1)

Пользователь открывает сайт, регистрацию или рабочую страницу без ожидания Telegram.
**Why this priority**: Сейчас внешняя библиотека может оставить пустой экран.
**Independent Test**: Запретить загрузку Telegram и открыть сайт.

**Acceptance Scenarios**:

1. **Given** Telegram недоступен, **When** открыта обычная web-страница, **Then** интерфейс и переходы работают без запроса библиотеки Telegram.
2. **Given** обычная страница уже открыта, **When** пользователь переходит на вход Mini App, **Then** начинается отдельное ожидание Telegram, а не показ ложного результата входа.

### User Story 2 — Управляемое ожидание Mini App (Priority: P1)

Запуск в Telegram показывает загрузку, успешный вход либо понятную ошибку с повтором.
**Why this priority**: Ускорение web не должно ломать существующий Telegram-вход.
**Independent Test**: Задержать библиотеку, затем разрешить её; отдельно отклонить и повторить.

**Acceptance Scenarios**:

1. **Given** библиотека ещё загружается, **When** пользователь ждёт, **Then** виден статус, а преждевременного входа или регистрации нет.
2. **Given** библиотека получена, **When** запуск валиден, **Then** используются существующие серверный вход и разрешённый target.
3. **Given** ошибка или ожидание дольше 10 секунд, **When** показан результат, **Then** доступны сообщение и повтор; повторный клик не запускает параллельную попытку.
4. **Given** запуск без данных Telegram, **When** библиотека загружена, **Then** сохраняется приглашение открыть приложение из Telegram, без запроса авторизации.

### User Story 3 — Сохранение текущих сценариев (Priority: P2)

Пользователь сохраняет безопасные переходы, перезагрузку Mini App, регистрацию и явный выход.
**Why this priority**: Нельзя создавать новые auth-flow ради исправления старта.
**Independent Test**: Перезагрузить целевую страницу Mini App; проверить выход и поздний ответ после ухода.

**Acceptance Scenarios**:

1. **Given** Mini App перешла на целевую страницу, **When** страница перезагружена в той же вкладке, **Then** библиотека снова подготавливается до Telegram-зависимого интерфейса.
2. **Given** пользователь явно вышел, **When** Mini App запускается снова, **Then** сохраняется существующее правило запрета автоматического восстановления.
3. **Given** попытка покинута, **When** приходит поздний ответ, **Then** он не завершает вход и не переключает маршрут.

### Edge Cases

Медленный/ошибочный/пустой ответ библиотеки; offline/retry; двойной клик; повторный mount;
переходы внутри приложения; запрет session storage; поддельные признаки Telegram в URL.
Признак запуска не является доказательством личности. Закрытые данные не выводятся в сообщения.

## Requirements

### Functional Requirements

- **FR-001**: Обычный сайт без признаков Telegram не запрашивает и не ждёт его библиотеку.
- **FR-002**: Вход Mini App, признаки запуска или повторное открытие его вкладки запускают подготовку Telegram до зависимых экранов.
- **FR-003**: Ожидание видно, ограничено 10 секундами; ошибка имеет явный повтор без перезагрузки страницы.
- **FR-004**: Повторные обращения разделяют одну активную попытку; поздние результаты покинутого ожидания не открывают экран.
- **FR-005**: При успехе сохраняются текущие темы, safe-area, разрешённые маршруты, вход/регистрация/выход.
- **FR-006**: Отсутствие данных запуска не превращается в авторизацию; проверка личности остаётся серверной.
- **FR-007**: Поддерживается перезагрузка внутри вкладки Mini App без нового копирования её закрытых данных в хранилища.
- **FR-008**: Ничего не очищает задачи, аккаунты или существующие пользовательские настройки.
- **FR-009**: Русские тексты, текущий знак Glowy, доступные статус и кнопка на 320–430 px и desktop.
- **FR-010**: Новые тесты используют только синтетические ответы, без реальной БД, Telegram-сессий и AI.
- **FR-011**: Отменённый серверный вход не применяет поздний успешный ответ.

### Key Entities

- Попытка подготовки: ожидание → готовность/ошибка → явный повтор.
- Признак вкладки Mini App: только факт контекста, без идентификаторов, данных входа или пользователя.
- Существующая серверная сессия: без изменений.

## Success Criteria

- **SC-001**: Все проверяемые обычные страницы работают при заблокированной библиотеке Telegram; число запросов к ней равно нулю.
- **SC-002**: В каждом сценарии зависшего Mini App старта ошибка с повтором появляется через 10 секунд ожидания.
- **SC-003**: Медленный успешный запуск проходит к разрешённому экрану без преждевременной авторизации.
- **SC-004**: Существующие автоматические сценарии Mini App и новые проверки desktop/mobile проходят.

## Assumptions

Используем текущие официальный источник библиотеки, backend и схемы входа. Повтор загрузки не
обещает отменить исполнение уже полученного внешнего скрипта. При запрещённом хранении данных
вкладки первичный запуск работает; сохранение контекста после удаления признаков URL при reload
не гарантируется (сама библиотека также зависит от среды Telegram).
Новые провайдеры, данные/платежи, production, push, миграции, env, редизайн LandingPage вне scope.
