# Feature Specification: Подтверждаемый план дня

**Feature Branch**: `codex/confirmable-day-plan`
**Created**: 2026-09-04
**Status**: Specified
**Input**: Продолжить автономное усиление продукта: превратить «Фокус дня» в понятный и подтверждаемый план без скрытых изменений данных.

## User Scenarios & Testing

### User Story 1 — Понять реалистичный следующий шаг (Priority: P1)

Пользователь видит в «Фокусе дня» небольшую очередь активных задач, подобранную по сроку,
приоритету, текущей энергии и ожидаемой длительности, а также краткую причину выбора первой задачи.

**Why this priority**: Glowy должен уменьшать неопределённость и помогать начать, а не только хранить список.
**Independent Test**: Подготовить задачи с разными сроками, приоритетами, нагрузкой и длительностью; менять энергию и проверять первую рекомендацию и размер очереди.

**Acceptance Scenarios**:

1. **Given** есть просроченная и будущая задачи, **When** открыта Главная, **Then** просроченная задача получает преимущество и объяснение срочности.
2. **Given** задачи одинаково срочны, **When** меняется энергия, **Then** выше оказывается задача с подходящей нагрузкой и длительностью.
3. **Given** активных задач больше дневной ёмкости, **When** показан план, **Then** видны только 1–3 шага в зависимости от энергии.

### User Story 2 — Проверить план до изменения задач (Priority: P1)

Пользователь открывает обзор плана, снимает или возвращает выбор отдельных задач и понимает,
какие из них уже стоят на сегодня, а какие будут перенесены.

**Why this priority**: Рекомендация не должна становиться скрытым изменением пользовательских данных.
**Independent Test**: Открыть обзор, изменить выбор и закрыть его; даты всех задач остаются прежними.

**Acceptance Scenarios**:

1. **Given** предложены задачи на другие даты, **When** пользователь открывает обзор, **Then** они отмечены как будущие изменения, но ещё не перенесены.
2. **Given** обзор открыт, **When** пользователь меняет выбор или закрывает окно, **Then** ни одна задача не изменяется.
3. **Given** задача уже на сегодня, **When** открыт обзор, **Then** это явно указано и повторная запись не требуется.

### User Story 3 — Явно применить выбранный план (Priority: P2)

Пользователь подтверждает обзор, после чего только выбранные задачи переносятся на сегодня через
существующий механизм обновления. Результат понятен даже при частичной ошибке.

**Why this priority**: Подтверждение превращает совет в полезное действие без нарушения контроля.
**Independent Test**: Подтвердить смешанный набор задач; проверить даты, сообщение об успехе и частичную ошибку.

**Acceptance Scenarios**:

1. **Given** выбраны задачи не на сегодня, **When** пользователь подтверждает план, **Then** только они получают сегодняшнюю дату.
2. **Given** выбрана задача уже на сегодня, **When** план подтверждён, **Then** лишний запрос обновления для неё не выполняется.
3. **Given** одно обновление завершилось ошибкой, **When** обработка закончена, **Then** успешные изменения сохраняются, окно остаётся открытым и пользователь видит количество неприменённых задач.

### Edge Cases

Нет активных задач; все рекомендации уже на сегодня; отсутствуют дата, длительность или категория;
одинаково подходящие задачи; офлайн-очередь существующего store; повторный клик во время применения;
задача исчезла до подтверждения; ширина 320–430 px. Пользовательские названия задач не отправляются
в продуктовую аналитику и не добавляются в новые логи.

## Requirements

### Functional Requirements

- **FR-001**: План использует только активные задачи и текущую энергию из существующего состояния приложения.
- **FR-002**: Очерёдность учитывает просрочку/сегодня, соответствие энергии, приоритет, длительность и стабильный запасной порядок.
- **FR-003**: Дневная ёмкость составляет одну задачу при энергии до 30%, две при 31–70% и три при 71–100%.
- **FR-004**: Первая рекомендация имеет короткое русское объяснение без утверждения, что её создал AI.
- **FR-005**: Обзор показывает рекомендуемую очередь и позволяет включать или исключать каждый пункт до подтверждения.
- **FR-006**: Открытие, изменение выбора и закрытие обзора не меняют задачи.
- **FR-007**: Явное подтверждение назначает сегодняшнюю дату только выбранным задачам, которые ещё не стоят на сегодня.
- **FR-008**: Во время применения повторное подтверждение недоступно; результат различает полный успех и частичную ошибку.
- **FR-009**: При частичной ошибке успешные обновления не откатываются, а неприменённые пункты остаются доступными для повтора.
- **FR-010**: Прямые карточки Главной остаются read-only; завершение, удаление и редактирование там не добавляются.
- **FR-011**: Интерфейс доступен с клавиатуры и пригоден на desktop и мобильной ширине 320–430 px.
- **FR-012**: Изменение переиспользует существующее обновление задач и не вводит новые API, AI-запросы, хранилища или схему БД.
- **FR-013**: Продуктовые события содержат только допустимые имена событий без названий задач и другого пользовательского текста.

### Key Entities

- **Кандидат плана**: существующая активная задача, её ранг, объяснение и признак «уже сегодня».
- **Черновик плана**: ограниченный список кандидатов и текущий набор выбранных идентификаторов; существует только пока открыт обзор.
- **Результат применения**: количество применённых, уже актуальных и неприменённых пунктов без пользовательских текстов.

## Success Criteria

- **SC-001**: Для любого набора активных задач отображается не более трёх рекомендаций, а первая соответствует документированному порядку.
- **SC-002**: До отдельного подтверждения автоматизированные проверки фиксируют ноль вызовов изменения задач.
- **SC-003**: После подтверждения каждая выбранная задача не на сегодня обновляется ровно один раз, невыбранные и уже сегодняшние — ноль раз.
- **SC-004**: Полный и частичный результат применения различимы пользователем не позднее завершения всех запущенных обновлений.
- **SC-005**: Сценарии обзора и подтверждения проходят на desktop и mobile; typecheck, lint, unit tests и production build успешны.

## Assumptions

Рекомендации вычисляются заново из текущего состояния и отдельно не сохраняются. Пустая дата допустима.
Существующий task store отвечает за optimistic/offline persistence. Рекомендация помогает выбрать
небольшой план, но не удаляет уже назначенные на сегодня задачи и не обещает календарную оптимизацию.
AI-подзадачи, расширенные фильтры, календарь, новые поля, backend, БД, env, production, push и
`LandingPage.tsx` находятся вне scope.
