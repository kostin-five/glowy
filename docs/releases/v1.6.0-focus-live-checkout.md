# Релиз v1.6.0 - Focus Live Checkout

## Обзор

Релиз v1.6.0 завершает переход от тестового payment foundation к production-ready потоку оформления тарифа Focus.

Цель релиза - сделать оплату Focus управляемой через feature flag, связать pricing UI с текущим тарифом пользователя и сохранить безопасный сценарий деплоя, при котором checkout можно держать выключенным до финального operational checklist.

## Изменения

### Pricing и Focus checkout

* обновлена логика `/pricing` для тарифа Focus;
* добавлен production-oriented CTA для оформления Focus;
* checkout доступен только при включенном `VITE_PAYMENTS_ENABLED`;
* при выключенном feature flag кнопка оплаты остается безопасно недоступной;
* active Focus state блокирует повторное оформление тарифа;
* current plan отображается на странице тарифов;
* добавлены состояния success/cancel после оплаты.

### Auth redirect

* сохранен redirect после login/register при переходе пользователя к оплате;
* сценарий `/pricing -> login/register -> pricing/checkout` стал предсказуемее;
* guest/auth переходы не теряют намерение пользователя оформить Focus.

### Backend payment flow

* используется существующий YooKassa payment foundation;
* backend создает платеж Focus и возвращает confirmation URL;
* webhook обрабатывает результат платежа;
* при успешной оплате обновляются `Payment` и тариф пользователя;
* повторная активация Focus защищена guard-логикой.

### Production safety

* платежный entry-point остается управляемым через env;
* секреты не попадают в отслеживаемые файлы;
* production включение оплаты требует отдельной настройки `YOOKASSA_*`;
* Prisma schema не менялась в рамках релиза v1.6.0.

## Проверки

Проверялись ключевые сценарии:

* `/pricing` при выключенных платежах;
* `/pricing` при включенном feature flag;
* отображение текущего тарифа;
* защита от повторного checkout для active Focus;
* redirect после авторизации;
* страницы `/payment/success` и `/payment/cancel`;
* отсутствие новых секретов в коде.

## Известные ограничения / что дальше

* перед production live checkout нужен отдельный pre-live checklist;
* production webhook URL и YooKassa env настраиваются вне кода;
* receipts/самозанятость/операционные проверки остаются отдельным процессом;
* AI limits пока не полностью tariff-aware и должны дорабатываться отдельной задачей.
