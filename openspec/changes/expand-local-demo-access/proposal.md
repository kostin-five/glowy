## Why

Публичное демо позволяет работать с задачами, но заметки обращаются к защищённому API, а часть прогресса и настроек недоступна гостю. Для портфолио нужен целостный локальный сценарий без аккаунта, AI-затрат и пользовательских записей в Neon.

## What Changes

- Открыть существующие не-AI возможности задач, заметок, привычек, прогресса, аналитики и локальных настроек в гостевом режиме.
- Добавить локальное сохранение недостающих сущностей; не выполнять гостевые запросы к защищённым API.
- Исключить ограничения подписки только для локальных demo-возможностей, не выдавая серверный тариф.
- Отключить AI во всех гостевых точках входа и показать понятное русское объяснение без перехода на login.
- Убрать показанные кнопку «Настроить план» и уведомление «План на сегодня готов» на главной. Заметки сохранить. Это трактовка ссылки на приложенный скриншот для review.
- Регистрация, checkout, привязка Telegram и серверная синхронизация остаются закрыты гостю.

## Capabilities

### New Capabilities

- `local-demo-access`: полный локальный не-AI сценарий и изоляция демо от аккаунтов и серверных интеграций.

### Modified Capabilities

Нет: новая capability задаёт отдельный гостевой контекст; требования существующих авторизованных сценариев сохраняются.

## Impact

Frontend: NotesPage/NoteApi, SuccessStairsPage, AnalyticsPage, ProfilePreferencesPanel, DashboardPage, AI clients/components и существующие Zustand/offline utilities. Добавляются локальные адаптеры и тесты; backend auth, квоты и Prisma остаются без ослабления. Документация demo-hosting и README уточняют возможности демо.

## Non-goals

Открытие регистрации, живые AI/платежи/Telegram гостю, новые продуктовые функции, правки LandingPage, миграции, очистка существующей Neon, deploy/push и переписывание истории.

## Runtime, data, production and rollback

Демо хранит данные только в браузере в отдельной гостевой области. Обновление не должно стирать существующие локальные задачи и не должно отправлять гостевые данные при последующем входе. Production меняется только после отдельного разрешения; rollback возвращает предыдущую сборку без удаления гостевых данных. Локальный режим не считается резервной копией и не обещает облачную синхронизацию.
