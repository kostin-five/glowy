# Data Model: Подтверждаемый план дня

Серверные сущности и база данных не меняются.

## Day plan candidate

- `task`: существующая активная Task;
- `isToday`: дата задачи совпадает с локальной сегодняшней датой;
- `reason`: одна безопасная UI-строка, вычисленная из метаданных задачи;
- `rank`: внутренний детерминированный порядок, отдельно не сохраняется.

## Day plan draft

- `candidates`: 1–3 первых кандидата согласно текущей энергии;
- `selectedTaskIds`: множество выбранных id, начально содержит всех кандидатов;
- lifecycle: создаётся при открытии → изменяется toggle → исчезает при cancel/success;
- не переживает reload и не считается пользовательскими данными вне текущего dialog.

## Apply result

- `applied`: задачи не на сегодня, для которых запущено существующее update;
- `unchanged`: выбранные задачи, уже стоящие на сегодня;
- `failed`: пункты, для которых update не вернул результат или завершился ошибкой;
- пользовательские названия не входят в метрики или логи результата.

## State transitions

`closed → review → applying → success/partial failure`. Cancel разрешён только до/после applying.
При partial failure `selectedTaskIds` сужается до failed; при success dialog закрывается.
