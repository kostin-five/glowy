# Feature Specification: Мобильная навигация заметок

**Feature Branch**: `codex/mobile-notes-navigation`

**Created**: 2026-09-03

**Status**: Complete

**Input**: Сделать заметки удобными на мобильных устройствах: вместо длинной страницы со списком и редактором показывать один понятный экран за раз, сохранив desktop-компоновку и безопасное автосохранение.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Открыть заметку без длинной прокрутки (Priority: P1)

На мобильном пользователь сначала видит список заметок. Выбор заметки или действие «Новая заметка» открывает отдельный редактор вместо добавления редактора под список.

**Independent Test**: Открыть `/notes` на ширине 320–430 px, выбрать существующую заметку и убедиться, что редактор заменил список без горизонтальной прокрутки.

**Acceptance Scenarios**:

1. **Given** мобильная ширина и маршрут `/notes`, **When** страница загружена, **Then** виден список, а редактор скрыт.
2. **Given** виден список, **When** пользователь выбирает заметку, **Then** открывается редактор выбранной заметки и список скрывается.
3. **Given** виден список, **When** пользователь нажимает «Новая заметка», **Then** открывается пустой редактор.
4. **Given** desktop-ширина, **When** пользователь работает с заметками, **Then** список и редактор остаются рядом.

---

### User Story 2 - Безопасно вернуться к списку (Priority: P1)

В мобильном редакторе пользователь видит действие «Назад к заметкам». Изменения сохраняются перед возвратом; при ошибке сохранения пользователь остаётся в редакторе и видит ошибку.

**Independent Test**: Изменить текст, нажать «Назад к заметкам», проверить вызов существующего API сохранения и возврат только после успеха; повторить с ошибкой API.

**Acceptance Scenarios**:

1. **Given** открыта неизменённая заметка, **When** пользователь возвращается к списку, **Then** список открывается без лишнего API-вызова.
2. **Given** есть несохранённые изменения, **When** пользователь возвращается, **Then** приложение сначала сохраняет их через существующий notes API.
3. **Given** сохранение завершилось ошибкой, **When** пользователь пытался вернуться, **Then** редактор остаётся открыт и показывает ошибку.
4. **Given** создаётся пустая заметка без текста, **When** пользователь возвращается, **Then** пустая запись не создаётся.

---

### User Story 3 - Сохранить ссылки и архивный сценарий (Priority: P2)

Прямой маршрут заметки, browser back и архивирование приводят к ожидаемому мобильному экрану, не меняя существующие связи заметки с задачами.

**Independent Test**: Открыть `/notes/:id`, вернуться browser back, затем архивировать заметку и проверить возврат к актуальному списку.

**Acceptance Scenarios**:

1. **Given** прямой маршрут `/notes/:id`, **When** страница загружена, **Then** мобильный редактор открывает указанную заметку.
2. **Given** заметка выбрана из списка, **When** пользователь использует browser back, **Then** открывается список заметок.
3. **Given** заметка успешно архивирована или восстановлена, **When** список обновлён, **Then** мобильный интерфейс возвращается к списку соответствующего раздела.

### Edge Cases

- Сохранение уже выполняется, когда пользователь нажимает возврат.
- Пользователь меняет текст во время незавершённого автосохранения.
- В URL передан отсутствующий или некорректный note id.
- Список пуст, идёт загрузка или API списка вернул ошибку.
- Экран меняет ширину между mobile и desktop во время редактирования.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: На ширинах меньше desktop breakpoint маршрут `/notes` MUST показывать список и MUST NOT размещать редактор ниже него.
- **FR-002**: Выбор заметки и «Новая заметка» MUST открывать редактор как единственную основную мобильную поверхность.
- **FR-003**: Мобильный редактор MUST иметь доступное действие «Назад к заметкам» с touch target не менее 44×44 px.
- **FR-004**: При `dirty` или `error` возврат MUST дождаться существующего save flow и закрыть редактор только после успеха.
- **FR-005**: Ошибка сохранения MUST оставить редактор открытым и MUST показать русское сообщение об ошибке.
- **FR-006**: Полностью пустая новая заметка MUST закрываться без создания записи.
- **FR-007**: Прямой маршрут `/notes/:id` MUST открывать соответствующий мобильный редактор.
- **FR-008**: Browser back с `/notes/:id` на `/notes` MUST возвращать мобильный список.
- **FR-009**: После успешного архивирования или восстановления мобильный интерфейс MUST возвращаться к списку и обновлять его.
- **FR-010**: На desktop список и редактор MUST сохранять текущую двухколоночную компоновку.
- **FR-011**: Существующие создание, редактирование, автосохранение, архив, task links и AI draft confirmation MUST продолжить использовать `NoteApi` без нового persistence слоя.
- **FR-012**: Экран MUST помещаться на ширинах 320, 360, 390 и 430 px без горизонтальной прокрутки.
- **FR-013**: Изменение MUST NOT затрагивать backend, Prisma, auth, AI contract, Telegram, тарифы, landing или production-конфигурацию.
- **FR-014**: Откат MUST быть возможен возвратом только frontend-компоновки и обработчика возврата без преобразования пользовательских данных.

### Key Entities

- **Режим мобильного экрана**: локальное UI-состояние `list` или `editor`, связанное с маршрутом выбранной заметки.
- **Состояние сохранения**: существующие `idle`, `dirty`, `saving`, `saved`, `error`, определяющие безопасность возврата.
- **Заметка**: существующая server entity; её контракт и поля не меняются.

## Success Criteria *(mandatory)*

- **SC-001**: На каждой целевой мобильной ширине список и редактор никогда не образуют одну длинную страницу.
- **SC-002**: В автоматических сценариях несохранённые изменения сохраняются до возврата в 100% успешных случаев.
- **SC-003**: При ошибке API редактор остаётся открыт в 100% проверенных сценариев, без потери введённого текста.
- **SC-004**: Desktop-компоновка, ссылки на задачи, AI-черновик и архивирование проходят существующие проверки без изменения API.
- **SC-005**: Typecheck, lint, unit/component tests, production build и релевантные Playwright проверки проходят.

## Assumptions

- Существующий breakpoint `lg` остаётся границей desktop-компоновки.
- На desktop действие возврата скрыто, так как список уже доступен рядом.
- Для новой непустой заметки возврат может создать запись через текущий `NoteApi.create`.
- Переключение экранов не требует анимации в этом slice.

## Out of Scope

- Новый backend, схема БД, offline-хранилище заметок или server-side drafts.
- Полнотекстовый редактор, папки, совместная работа или история версий.
- Изменение AI-генерации задач из заметки.
- Общий визуальный редизайн desktop-настроек или других вкладок.
