# Release v1.5.2 - Security Hotfix

## Summary
This release focuses on hardening the security of the Glowy application before the commercial v2.0.0 release. It includes protections against CSRF, brute-force attacks, and user enumeration, as well as improved backend validation.

## Changes

### Backend
- **CSRF Protection**: Added middleware to check `Origin` and `Referer` headers for unsafe HTTP methods (`POST`, `PUT`, `PATCH`, `DELETE`).
- **Rate Limiting**: 
  - Implemented strict rate limits for `/api/auth/login` (5 attempts per 15 min) and `/api/auth/register` (10 attempts per 1 hour).
  - Added IP + Email based key generation for login rate limiting.
- **Safe Auth Errors**: Unified error messages for login and registration to prevent user enumeration. 
  - Login: "Неверный email или пароль".
  - Registration: "Пользователь с таким email уже существует" or "Не удалось создать аккаунт".
- **Dev Protection**: Added `X-Robots-Tag: noindex, nofollow` for `dev.glowy-ai.ru` domain.
- **Endpoint Security**: Secured `/api/chat` with authentication middleware.
- **Validation**: Added server-side validation using `express-validator` for tasks, subtasks, and user energy endpoints.
- **CORS Audit**: Restricted production origins to `https://glowy-ai.ru` and `https://www.glowy-ai.ru`.

### Frontend
- **API Config**: Removed automatic fallback to localhost in production. `VITE_API_URL` is now strictly required.
