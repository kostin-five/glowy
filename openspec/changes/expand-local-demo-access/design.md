## Context

См. proposal.md. NotesPage всегда вызывает NoteApi; гостевой запрос к защищённому API может запускать общий logout/login flow. SuccessStairsPage отключает progress query для гостя и блокирует вкладки, кроме XP. ProfilePreferencesPanel запрещает гостю сохранение и выставляет canUseFocusFeatures=false. У задач уже есть ветки isGuest, Zustand persistence и IndexedDB/offline-инфраструктура; они должны быть сохранены, а не заменены.

## Goals / Non-Goals

**Goals:** локальные аналоги существующих не-AI операций, явная граница сетевого доступа и изоляция контекстов; проверка каждой пользовательской точки входа.

**Non-Goals:** новый backend для демо, fake JWT/аккаунт/подписка, генерация синтетических данных в PostgreSQL, изменение LandingPage или production-конфигурации.

## Decisions

1. Локальный demo data adapter с типами существующих контрактов, версионированным guest namespace и IndexedDB для заметок/привычек/прогресса. Локальные UI-настройки сохраняются существующим scoped settings store. Не создавать новый общий auth store. Альтернативы: серверный общий demo-аккаунт отвергнут из-за смешивания данных; только React state отвергнут из-за потери данных при reload.
2. Выбирать локальные операции по isGuest на границе API/hooks до сетевого запроса. Не превращать общие 401 в успех и не изменять глобально entitlement аккаунта. SuccessStairsPage и AnalyticsPage получают локальный обзор; повторно использовать чистые расчёты и общие типы, сверять семантику с серверными правилами.
3. Заметки переиспользуют существующие UI и контракты; локальная валидация, поиск/архив и note-task links соответствуют требованиям notes. Обрабатывать удаление задач и смену session scope, включая поздние async результаты. Существующие гостевые задачи не переносить в серверную offline queue.
4. Централизованный запрет AI в клиентском слое дополняется выключенными UI действиями. Проверить все методы AiApi, NoteApi AI, AnalyticsApi AI и точки MindHubChat/subtask draft. Backend auth/limits остаются неизменными; клиентская блокировка не считается серверной защитой.
5. Удалить только показанный ручной flow настройки плана DashboardPage: кнопку, диалог и связанное уведомление, не меняя LandingPage. Сохранить остальные полезные блоки и ручное управление задачами. Для авторизованной главной удаление этих же элементов оформлено как общее UI-упрощение.
6. Не применять subscription gates к локальным не-AI возможностям, но не выдавать гостю plan=focus/forever и не открывать checkout. AI tone остаётся неактивным AI-параметром; аватар и обычные настройки доступны локально.

## Risks / Trade-offs

- [Дублирование расчётов прогресса] → переиспользовать чистую логику, тестировать границы дат, повтор отметки и спасательного круга; не добавлять новые правила.
- [Смешивание данных при входе] → отдельный namespace, проверка scope для поздних ответов, тесты guest → account → guest и отсутствие загрузки данных на backend.
- [Потеря локальных данных] → версионированное хранилище, сохранение существующих ключей задач, понятные ошибки quota/storage; не обещать cloud backup.
- [Забытый AI endpoint] → запрет в клиентском слое и E2E контроль сети на всех гостевых AI действиях.
- [Слишком широкое слово «все»] → только уже существующие локально воспроизводимые возможности; аккаунтные интеграции, облако, платежи и AI явно исключены.

## Migration Plan

Новая версия frontend добавляет guest-only storage без изменения Prisma. Перед реализацией создать codex/* ветку от проверенной dev. Проверить старые гостевые задачи после обновления и все новые сценарии без записи в Neon. Deploy/push только по отдельному согласию после проверок. Rollback frontend сохраняет guest storage и не меняет серверные данные. README и demo-hosting описывают локальные возможности и исключения. Текущий prepare-public-pet-project не архивировать до внешних gates.
