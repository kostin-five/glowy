# Tasks and Subtasks Specification

## Purpose

Определяет основной пользовательский контракт Glowy для захвата, планирования, выполнения и
безопасного изменения задач и их шагов.

## Requirements

### Requirement: Управление задачами

Авторизованный пользователь SHALL получать только свои задачи и SHALL иметь возможность создавать,
изменять и удалять их с полями title, date, priority, category, energyLevel, estimatedMinutes и
actualMinutes.

#### Scenario: Создание допустимой задачи
- **WHEN** пользователь сохраняет задачу с непустым title и допустимыми необязательными полями
- **THEN** backend создаёт задачу текущего аккаунта и возвращает её по общему контракту

#### Scenario: Некорректные поля
- **WHEN** title пуст, дата не соответствует `YYYY-MM-DD` или длительность вне допустимого диапазона
- **THEN** backend отклоняет запрос и не создаёт или не изменяет задачу

### Requirement: Единый контракт даты

Frontend и backend MUST передавать календарную дату задачи как `YYYY-MM-DD` либо пустую строку без
locale-зависимого преобразования.

#### Scenario: Задача без даты
- **WHEN** пользователь не выбирает срок
- **THEN** API и локальное состояние сохраняют пустую строку

### Requirement: Управление подзадачами

Пользователь SHALL создавать, переименовывать, отмечать, переупорядочивать и удалять подзадачи
только внутри принадлежащей ему задачи; выдача SHALL иметь устойчивый порядок position, createdAt,
id.

#### Scenario: Переупорядочивание шагов
- **WHEN** пользователь сохраняет новый порядок принадлежащих задаче подзадач
- **THEN** backend обновляет их позиции в одной task update операции и последующая выдача сохраняет порядок

#### Scenario: Чужая задача
- **WHEN** пользователь обращается к подзадаче или родительской задаче другого аккаунта
- **THEN** backend не раскрывает и не изменяет подзадачу

### Requirement: Завершение и XP

Первое завершение задачи SHALL фиксировать completedOn, начислять или корректировать XP ровно один
раз и возвращать итоговый progress и объяснимый completion outcome. Повторное открытие и завершение
не SHALL начислять XP повторно.

#### Scenario: Первое завершение
- **WHEN** незавершённая задача отмечается выполненной с допустимой текущей локальной датой
- **THEN** backend атомарно сохраняет completion, `xpAwarded` и обновлённый уровень пользователя

#### Scenario: Повторное завершение
- **WHEN** ранее награждённую задачу открывают и снова завершают
- **THEN** состояние задачи меняется без повторной награды XP

### Requirement: Поведенческий режим завершения

Glowy MUST применять выбранный backend-профиль calm, moderate или strict к XP при наличии другой
активной просроченной задачи, не опуская XP ниже нуля и не наказывая завершение самой просроченной
задачи.

#### Scenario: Strict при активной просрочке
- **WHEN** пользователь в strict-режиме завершает непросроченную задачу при наличии другой просроченной
- **THEN** backend один раз вычитает обычную награду в пределах текущего XP и возвращает причину

### Requirement: Черновики не равны сохранённым задачам

Любой AI-план, набор шагов или task draft SHALL оставаться редактируемым черновиком до явного
подтверждения пользователя.

#### Scenario: Пользователь отклоняет черновик
- **WHEN** пользователь получает AI-черновик и не нажимает подтверждение
- **THEN** ни задача, ни подзадачи не создаются и существующие записи не изменяются
