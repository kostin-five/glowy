# Архитектура Glowy

## Границы системы

```text
Браузер / мини-приложение Telegram
  -> клиентская часть: React + TypeScript + Vite
  -> HTTPS API
  -> серверная часть: Express + TypeScript
  -> общие Zod-схемы и типы (packages/contracts)
  -> единый клиент Prisma -> PostgreSQL в Neon

Серверная часть -> DeepSeek API
               -> GigaChat API при временной ошибке основного провайдера
               -> API ЮKassa

Уведомления ЮKassa -> Express -> PostgreSQL
Уведомления Telegram -> Express -> очередь PostgreSQL -> фоновый обработчик -> Bot API
```

Клиентская часть размещена на Vercel, серверная — на Render.
Запросы `/api` перенаправляются через Vercel к серверу.

## Клиентская часть

`src/pages/` собирает маршруты и экраны. `src/api/` отвечает за HTTP-запросы,
`src/store/` — за состояние Zustand. Общие компоненты находятся в
`src/components/`, чистые вспомогательные функции — в `src/utils/`.
Ключи AI-провайдеров, ЮKassa и базы данных в браузер не передаются.

На экранах уже порога `lg` компонент `BottomNav` показывает «Главную», «Задачи»,
«Ассистента», «Мой прогресс» и «Ещё». Центральная сфера открывает модальное окно
«Разгрузки мыслей», выезжающее снизу. «Ещё» открывает ссылки на аналитику и
настройки. Headless UI удерживает фокус внутри окна, обрабатывает Escape и
возвращает фокус после закрытия. Окна закрываются при смене маршрута.

Список задач хранится в Zustand. Поиск, сортировка и фильтры применяются локально.
Фильтры срока, энергии, приоритета и категории объединяются по правилу И.
Они не записываются в профиль или API и сбрасываются вместе с сессией экрана.

## Серверная часть и база

Express обрабатывает CORS, CSRF, идентификаторы запросов и HTTP-маршруты.
Единственный клиент Prisma и пул соединений создаются в `backend/lib/prisma.ts`.
Импорты в режиме NodeNext используют суффикс `.js` для скомпилированных модулей.
PostgreSQL хранит пользователей, задачи, подзадачи, платежи и состояние тарифов.

Серверная часть написана на TypeScript. После компиляции в `backend/dist/`
она запускается через `node dist/server.js`, без дополнительного загрузчика.
Общие Zod-схемы и типы находятся в `packages/contracts`. Сервер проверяет
входные данные, клиент повторно проверяет полученный ответ.

Маршруты определены в `backend/routes/`. Их перечень находится в
[документации API](api-endpoints.md), перечень исходных файлов —
в [документации серверной части](backend-source-inventory.md).

## AI и «Разгрузка мыслей»

`backend/routes/ai.routes.ts` использует сервисы в `backend/services/ai/`.
Основной провайдер — DeepSeek. При превышении времени ожидания, сетевой ошибке,
HTTP 429 или HTTP 5xx выполняется одна попытка через GigaChat.
Успешный запрос не отправляется двум провайдерам. Короткоживущий OAuth-токен
GigaChat хранится в памяти процесса. Ключи остаются на сервере.

Ответ содержит текст и необязательные несохранённые черновики задач.
AI не создаёт и не меняет задачи. Пользователь редактирует или отклоняет черновик;
только подтверждение вызывает API задач. Текст сообщений и задач не передаётся
в аналитические события.

`POST /api/ai/subtask-draft` использует общий защищённый маршрут и лимит.
Ответ нормализуется в 2–8 уникальных коротких шагов без записи в `Task` и
`SubTask`. При создании задачи шаги остаются в локальной форме до сохранения.
При редактировании подтверждённые шаги создаются через API подзадач;
неуспешные остаются в редакторе для повторной попытки.

Суточная квота резервируется атомарно до обращения к провайдеру.
При ошибке резерв освобождается в том же временном окне.
Общее время ожидания ограничено для основного и резервного провайдеров.
После трёх временных ошибок обращения приостанавливаются на 30 секунд,
затем допускается один пробный запрос. Состояние этой защиты хранится в
памяти процесса и сбрасывается при его перезапуске.

Быстрое окно и страница `/ai` используют общий `MindHubChat`, `AiApi` и
локальное хранилище разговора. Ожидающие черновики не становятся задачами до
подтверждения. Серверной истории разговоров и их синхронизации между
устройствами пока нет. В гостевом режиме AI-запросы не отправляются.

## Оплата

Клиент обращается к серверу для оформления платежа. Сервер создаёт платёж в
ЮKassa и возвращает адрес подтверждения. После уведомления он повторно
проверяет платёж у провайдера, сумму, валюту и дополнительные данные.
Повторная обработка уведомления не выдаёт доступ заново.
Страница результата оплаты не является источником истины.

Пожизненный доступ обозначается тарифом `forever`. Бесплатная активация
отключена: совместимый маршрут возвращает `410 PLAN_UNAVAILABLE` до обращения
к базе. Существующие и вручную назначенные права проверяются на сервере.
Новые покупки выключены настройкой окружения.

## Аналитические отчёты

Сформированный отчёт сохраняется в `localStorage` браузера. Ключ включает
пользователя, период и даты. При смене аккаунта или периода чужой отчёт
не показывается. Интерфейс поддерживает ограниченный Markdown без HTML.
Удаление явное; новый AI-разбор требует подтверждения и заменяет прежний
только после успешного ответа. Серверной истории и синхронизации отчётов нет.

## Мини-приложение Telegram и бот

Маршрут `/telegram` запускает существующее React-приложение внутри Telegram.
Он передаёт исходные `initData` только в серверный маршрут авторизации.
После проверки открываются те же защищённые страницы, что и в браузере.
Отдельного профиля или хранилища данных для Telegram нет.
Интеграция учитывает тему, размер окна, безопасные отступы, кнопку «Назад»
и внешние HTTPS-ссылки.

Обычный сайт не загружает Telegram SDK без признаков запуска мини-приложения.
Одна общая попытка загрузки ограничена 10 секундами; после ошибки доступен
явный повтор. Маркер в `sessionStorage` хранит только контекст вкладки,
не данные авторизации. Проверка личности выполняется на сервере.

Сервер принимает подписанные данные не позднее пяти минут после `auth_date`.
Связь `TelegramConnection` создаётся в транзакции. Связанная с Telegram
HttpOnly-сессия живёт не более 24 часов и сверяется с текущей привязкой.
Отвязка сразу делает такую сессию недействительной, но не удаляет аккаунт
и задачи. Одноразовый код привязки из настроек сайта действует 10 минут.

Вход использует общие `LoginPage` и `RegisterPage`. Обычный выход завершает
сессию, но не удаляет привязку Telegram. Локальный маркер запрещает
автоматическое восстановление до следующего ручного входа.
Регистрация в демонстрационном окружении закрыта.

Маршрут `/api/telegram/webhook` проверяет
`X-Telegram-Bot-Api-Secret-Token`, сохраняет обновление без дублирования и
сразу отвечает. Фоновый обработчик использует ту же PostgreSQL и общий
клиент Prisma. После обработки содержимое обновления очищается.
Логи не содержат сообщений, токенов, идентификаторов Telegram или кодов.

Бот поддерживает `/today`, `/tasks`, `/energy`, `/progress`,
подтверждаемые `/add` и `/done`, а также `/ai` с общим AI-лимитом.
HTTP и Telegram используют общий сервис завершения задач и начисления опыта.
Повторное нажатие не дублирует результат. Голосовые сообщения не скачиваются
и не отправляются в платное распознавание речи; бот предлагает текстовый ввод.

API прогресса возвращает календарь выбранного месяца по данным текущего
пользователя. «Спасательный круг» применим только к вчерашнему разрыву,
если позавчера уже входило в серию.

## Локальный фон

Выбранный фон хранится в Zustand и сохраняется в `glowy-settings`.
Встроенные варианты — разрешённые CSS-градиенты без сетевой загрузки.
Неизвестное значение заменяется на `midnight`.

Собственное изображение PNG, JPEG или WebP до 5 МБ сохраняется одним Blob
в IndexedDB `glowy-personalization`. Оно не попадает в API и не
синхронизируется с аккаунтом. `useAppWallpaper` создаёт временный адрес
изображения и освобождает его при замене или удалении компонента.
При ошибке показывается встроенный фон.

`AppLayout` размещает фон под содержимым, а затемняющий слой сохраняет
контраст. Главная рекламная страница, страницы входа и правовые документы
не меняются. Полноэкранный `MindHubChat` использует полупрозрачные слои,
чтобы выбранный фон оставался видимым.

## Заметки

`NotesPage` использует общий `NoteApi`. На широком экране список, редактор
и сведения о заметке находятся в одной области, на узком — открываются
последовательно. Отображаются `createdAt`, `updatedAt`, связи `taskLinks`
и подготовка AI-черновика из выделенного текста. Папки, теги, избранное и
расширенное форматирование не имитируются. Автосохранение, архив, связи и
подтверждение создания задачи сохраняют прежние API-контракты.

## Логи и тесты

Каждый запрос получает серверный `X-Request-Id`. Структурированные логи
содержат только разрешённые технические поля: метод HTTP, шаблон маршрута,
статус, длительность и идентификатор запроса. Тела запросов, cookie,
токены, почта, тексты задач и AI-сообщений не записываются.

Ошибки критических разделов сохраняют совместимое поле `message` и
добавляют `code` и `requestId`. Логи провайдера ограничены техническими
данными о состоянии, задержке, использовании и стоимости.

CI проверяет типы, стиль кода, модульные и браузерные тесты, сборку и
изолированные HTTP-тесты серверной части. Рабочая база в тестах не используется.
Проверки с реальной Prisma-базой требуют отдельной тестовой базы.
