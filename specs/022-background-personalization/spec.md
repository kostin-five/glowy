# Feature Specification: Персонализация фона

**Feature Branch**: `codex/background-personalization`  
**Created**: 2026-09-04  
**Status**: Implemented  
**Input**: Сделать фон Glowy немного темнее и позволить пользователю выбрать предложенные обои или загрузить собственные, продолжая автономную разработку без production и push.

## Clarifications

### Session 2026-09-04

- В первом slice выбор и пользовательский файл хранятся только на текущем устройстве и не синхронизируются с аккаунтом.
- Встроенные варианты реализуются CSS-фонами без новых тяжёлых изображений; стандартный фон становится немного темнее.
- Пользовательская загрузка принимает PNG, JPEG или WebP размером до 5 МБ. SVG и анимированные форматы не принимаются.
- Пользовательский файл хранится Blob-объектом в IndexedDB, а в существующем localStorage остаётся только выбранный идентификатор.
- Любые обои получают постоянный тёмный защитный слой, чтобы карточки и текст сохраняли читаемость.
- Персонализация действует только внутри авторизованной оболочки приложения и не затрагивает landing, вход или юридические страницы.

## User Scenarios & Testing

### User Story 1 — Выбрать спокойный фон (Priority: P1)

Пользователь открывает раздел «Интерфейс» и выбирает один из предложенных вариантов, сразу видя результат во всём приложении.

**Independent Test**: выбрать каждый вариант, перейти на другую вкладку и перезагрузить страницу; выбранный фон остаётся активным.

**Acceptance Scenarios**:

1. **Given** используется стандартный вид, **When** пользователь выбирает встроенный фон, **Then** оболочка обновляется без перезагрузки и показывает подтверждение сохранения.
2. **Given** встроенный фон уже выбран, **When** приложение открывается снова, **Then** выбор восстанавливается из локальных настроек.
3. **Given** активна светлая тема, **When** выбираются обои, **Then** контент и текст остаются читаемыми.

### User Story 2 — Использовать своё изображение (Priority: P1)

Пользователь выбирает фотографию на устройстве и после успешной проверки применяет её как локальный фон.

**Independent Test**: загрузить допустимый WebP/JPEG/PNG, проверить применение и восстановление после reload без сетевого запроса.

**Acceptance Scenarios**:

1. **Given** выбран поддерживаемый файл до 5 МБ, **When** загрузка завершена, **Then** Blob сохраняется локально и фон применяется.
2. **Given** выбран неподдерживаемый или слишком большой файл, **When** приложение проверяет его, **Then** фон не меняется и показано понятное русское сообщение.
3. **Given** локальное хранилище недоступно, **When** сохранение не удалось, **Then** текущий фон сохраняется и пользователь видит ошибку без белого экрана.

### User Story 3 — Вернуться к стандартному виду (Priority: P2)

Пользователь одним действием выбирает стандартный фон или удаляет своё локальное изображение.

**Independent Test**: применить собственный фон, удалить его и убедиться, что Blob удалён, а стандартный фон восстановлен.

## Requirements

### Functional Requirements

- **FR-001**: Стандартный тёмный фон оболочки должен стать визуально немного темнее без изменения логотипа и сферы Glowy.
- **FR-002**: Настройки должны предлагать стандартный фон и минимум два спокойных встроенных варианта с превью.
- **FR-003**: Выбор встроенного фона должен сохраняться в существующем settings store и применяться без перезагрузки.
- **FR-004**: Пользовательская загрузка должна принимать только PNG, JPEG и WebP до 5 МБ.
- **FR-005**: Пользовательское изображение должно храниться локально в IndexedDB и никогда не отправляться на backend.
- **FR-006**: При активном пользовательском изображении оболочка должна создавать object URL, освобождать его при замене/unmount и сохранять читаемый затемняющий слой.
- **FR-007**: Ошибка чтения, валидации или IndexedDB не должна менять текущий фон или ломать приложение.
- **FR-008**: Должно быть явное действие удаления пользовательского изображения и возврата к стандартному виду.
- **FR-009**: Управление должно быть доступно с клавиатуры и помещаться на ширине 320–430 px.
- **FR-010**: Изменение не должно требовать backend, Prisma, миграции, env, production, push или изменения `LandingPage.tsx`.

## Success Criteria

- **SC-001**: Unit tests подтверждают нормализацию старых/повреждённых настроек и переключение вариантов.
- **SC-002**: Storage tests подтверждают запись, чтение и удаление Blob без сериализации изображения в localStorage.
- **SC-003**: Component tests подтверждают допустимую загрузку, понятные ошибки и сброс.
- **SC-004**: Новый код проходит focused tests и TypeScript; полный release gate выполняется вместе с общим pre-3.0.0 завершением.

## Out of Scope

Синхронизация обоев между устройствами, серверная галерея, публичные профили, монетизация обоев, crop-редактор, ручная настройка blur/brightness, landing и production.
