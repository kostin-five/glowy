## Why

Glowy переводится в публичный портфолио-проект после прекращения оплаченного размещения. Требуется исправить выявленные нарушения безопасности, подготовить обезличенную публичную документацию и воспроизводимый запуск на бесплатной инфраструктуре.

## What Changes

- Проверяемый TLS PostgreSQL и единая квота для всех AI-вызовов, включая анализ задач.
- Защита login, отзыв сессий, безопасные ошибки и browser logs, security headers, ограниченная proxy/CORS-конфигурация.
- Ограничение webhook-нагрузки, timeout и атомарная обработка повторных платежных событий.
- Безопасные env examples, ignore rules и публичный README без operational-доступов и неподтверждённых результатов.
- Подготовка frontend на Vercel, существующего backend на Render с веткой master и выключенным автодеплоем, PostgreSQL на Neon. Новая база остаётся пустой после создания схемы: без seed, demo-аккаунтов, задач и платежей. Восстановление старой базы не выполняется без подтверждённой копии.
- Отключение новой регистрации на сервере, включая Telegram Mini App, с сохранением гостевого режима в браузере и входа существующих аккаунтов; блокирующая CSP после браузерных проверок.
- Согласованная локальная очистка исторических внутренних документов, старых личных реквизитов и только авторских email владельца в изолированной копии Git после проверенного backup, без изменения исходного checkout и удалённых refs.
- Персональные реквизиты и внутренние документы получают отдельный manifest для согласованного обезличивания. Сам manifest не содержит исходных персональных значений.

## Capabilities

По подтверждению владельца удалить Яндекс Метрику, встроенный счётчик, env-настройку,
отправку продуктовых событий и аналитический баннер. Технические auth cookies сохраняются.

### New Capabilities

- `public-project-security`: требования к защите публичного портфолио-проекта, упаковке исходников и подготовке нового размещения.

### Modified Capabilities

Нет удаления действующих требований к контролю доступа, AI-квотам и проверке платежей. Дополнительные требования описаны в новой capability.

## Impact

Затрагиваются общий PostgreSQL adapter, auth middleware/services/routes, AI routes, payment routes, error middleware, frontend logging, env/config, README и публичная документация. Возможны новые аддитивные таблицы для отзыва сессий; выбор фиксируется в design.

Runtime: новые проверки могут отвергать ранее допускавшиеся небезопасные запросы. Данные: восстановление только из подтверждённой копии; отсутствие копии не означает разрешение удалить старые данные. Production: внешнее размещение, DNS и webhook выполняются отдельным согласованным шагом. Rollback: сохраняются резервная копия и прежняя конфигурация, без возврата обхода квот или отключения TLS.

## Non-goals

Новая продуктовая разработка, изменение лицензии без выбора владельца, выдача платных прав всем пользователям, несогласованное удаление истории, force push и изменение видимости GitHub. Живая оплата и перенос персональных данных за рубеж требуют отдельного решения владельца. Исходники платежной интеграции и тесты сохраняются. Тестовые данные в PostgreSQL не создаются.
