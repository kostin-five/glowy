# v2.1.0 -- Quality Baseline

Статус: в разработке.

## Выполнено в ветке

- Добавлен Error Boundary для lazy-маршрутов с русским экраном восстановления и компонентными
  тестами.
- Добавлен consent-aware helper для продуктовых событий Яндекс Метрики. Он принимает только
  утверждённые имена событий и UTM-параметры, не передаёт пользовательский текст.
- Добавлены события регистрации, первой созданной задачи, первого AI-запроса и старта checkout
  Focus. `ai_draft_confirmed` остаётся задачей v2.2.
- Backend выделен в тестируемый `app.js`; добавлены `X-Request-Id`, безопасный структурированный
  logger и global error middleware.
- Добавлены изолированные HTTP-тесты backend для health, CORS, request ID и generic error.
- CI дополнен production build и backend HTTP tests.

## Зафиксированный baseline

- `npm run build` проходит; самый крупный lazy chunk -- `charts` (около 117 kB gzip), он не
  блокирует публичный стартовый экран.
- Playwright проверил landing и регистрацию на 360, 390 и 430 px: горизонтального переполнения не
  обнаружено.

## Перед выпуском

- Выполнить все команды из [release-checklist.md](../release-checklist.md).
- Прогнать mobile smoke на 360, 390 и 430 px и записать только реальные найденные проблемы.
- Настроить цели и сохранённый отчёт в Яндекс Метрике вручную; проверить Яндекс Вебмастер и Google
  Search Console. Это требует доступа владельца аккаунтов.
- Не менять Landing Page и не добавлять `landing_cta_click` без отдельного продуктового решения.

## Известные границы

- В v2.1 не добавляются миграции, новые тарифы, платежные сценарии или database-dependent tests.
- События «первая задача» и «первый AI-запрос» ограничены сессией браузера. Для точной
  lifetime-активации нужна отдельная серверная модель событий в следующем этапе аналитики.
