# Research: Подтверждаемый план дня

## Decision 1: детерминированная рекомендация без AI

**Decision**: сортировать активные задачи локально по срочности, соответствию текущей энергии,
приоритету, длительности и стабильному заголовку/id; размер очереди зависит от энергии.

**Rationale**: результат мгновенный, объяснимый, бесплатный и не создаёт ещё один AI-flow.

**Alternatives considered**: отправлять весь список в AI — дороже, раскрывает больше данных и
требует нового backend-контракта; случайный выбор — не объясним и нестабилен.

## Decision 2: обзор является временным черновиком

**Decision**: выбранные id хранятся только в состоянии открытого dialog. Открытие, toggle и cancel
не вызывают store; confirm обновляет только выбранные задачи не на сегодня.

**Rationale**: это буквально выполняет правило явного подтверждения и не вводит новую сущность плана.

**Alternatives considered**: автоматически переносить рекомендации — нарушает контроль; сохранять
отдельный план на backend — требует схемы, API и сложной синхронизации раньше доказанной пользы.

## Decision 3: частичный успех не маскируется

**Decision**: выполнять независимые updates, затем оставить dialog открытым только с неуспешными
пунктами и показать их количество; успешные optimistic/offline обновления не откатывать.

**Rationale**: существующий store уже отвечает за доставку/offline queue, а UI не заявляет ложный успех.

**Alternatives considered**: `Promise.all` с первым rejection скрывает остальные результаты;
клиентский rollback противоречил бы уже поставленным в offline queue операциям.

## Decision 4: измерять только безопасные действия

**Decision**: allowlist события открытия и успешного применения без параметров и пользовательского текста.

**Rationale**: можно оценить использование функции, не расширяя сбор данных.

## Open Questions

Нет вопросов, меняющих реализацию. Проверка полезности требует будущих реальных пользователей,
но не является блокером безопасного локального slice.
