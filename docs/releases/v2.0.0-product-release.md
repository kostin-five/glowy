# Релиз v2.0.0 - Product Release

## Обзор

Релиз v2.0.0 переводит Glowy от production MVP к более цельному продукту вокруг задач, AI-планирования, энергии и прогресса.

Главный фокус релиза - Tasks 2.0 и продуктовая сборка вокруг Mind Hub: более устойчивый data contract для дат, улучшенное отображение задач, мобильный UX, множественный выбор, сортировка, группировка, Dashboard 2.0, tariff-aware AI limits, Focus checkout и бесплатная активация Forever для первых пользователей.

## Изменения

### Tasks 2.0

* обновлена страница `/tasks`;
* доработаны вкладки задач:
  * `Активные`;
  * `Выполненные`;
  * `Все`;
* во вкладках добавлены счетчики задач;
* улучшены поиск, сортировка и переключение list/grid;
* исправлено поведение FAB на мобильных и средних экранах;
* добавлен режим множественного выбора задач;
* добавлена bulk-панель действий;
* добавлены массовые действия для выбранных задач;
* улучшены create/edit модалки;
* добавлена placeholder-кнопка AI с сообщением, что функция скоро появится;
* устранены конфликтующие чекбоксы selection/completion;
* улучшена адаптация под узкие экраны.

### Unified date contract

Для задач введен единый frontend-contract:

```text
Task.date = "YYYY-MM-DD" | ""
```

Что сделано:

* добавлена нормализация дат во frontend-слое;
* legacy `DD.MM.YYYY` поддерживается как входной формат;
* пустая дата сохраняется как `""`;
* UI больше не должен рендерить raw `task.date`;
* карточки задач используют форматтер для отображения даты;
* группировка и сортировка используют безопасный local-date parser;
* снижены риски timezone bugs от прямого `new Date("YYYY-MM-DD")`.

### Task grouping и sorting

* добавлена группировка задач по дате;
* заголовки групп показывают понятные подписи:
  * `Сегодня`;
  * `Завтра`;
  * `Вчера`;
  * `5 июля`;
  * `5 июля 2026`;
  * `Без даты`;
* сортировка по названию отображается без date group headers;
* для сортировок по дате, приоритету, энергии и категории используются групповые разделители;
* добавлены прямые и обратные варианты сортировок;
* исправлена логика, при которой сортировка менялась только внутри одного дня.

### Task cards UI

* удалено raw date rendering;
* дата в карточках отображается через единый formatter;
* карточки стали стабильнее в list mode;
* drag overlay использует тот же UI-format для даты;
* сохранены действия:
  * завершение задачи;
  * удаление;
  * редактирование;
  * добавление подзадач;
  * drag-to-trash.

### Analytics 2.0

* обновлен `/analytics`;
* добавлен недельный график выполненных задач;
* добавлено переключение последних недель;
* tooltip графика показывает день и дату;
* исправлен визуальный focus на графике при нажатии;
* улучшена мобильная компоновка аналитики.

### Dashboard / Пункт управления

* обновлен `/dashboard` как рабочий command center;
* добавлен блок `Фокус дня` с rule-based выбором до двух активных задач;
* выбор фокуса учитывает дату задачи и текущую энергию пользователя;
* добавлены compact task previews для задач на сегодня;
* добавлен блок задач, созданных через Mind Hub;
* для AI-created задач используется frontend-only tracking через `localStorage`;
* добавлена плашка низкого заряда при `currentEnergy <= 20`;
* улучшен блок `Энергия на сегодня`;
* добавлен единый визуальный стиль scrollbar для страниц и внутренних scroll-зон.

### Progress ladder

* обновлен `/stairs`;
* лестница прогресса стала главным визуальным блоком страницы;
* текущий уровень вынесен после лестницы;
* правила начисления XP спрятаны в popup-подсказку;
* добавлен блок `XP за сегодня`;
* улучшена responsive-компоновка карточек;
* увеличены визуальные элементы лестницы на больших экранах.

### Mind Hub / AI 2.0

* убраны ручные режимы `Диалог` / `В задачи` из интерфейса;
* Mind Hub работает в auto-flow: сам определяет, где ответить поддержкой, а где создать задачи;
* добавлена история сообщений в Хабе мыслей;
* добавлена очистка истории чата;
* AI получает контекст активных задач пользователя;
* AI проверяет дубли задач и не должен создавать повтор без явного запроса;
* добавлены AI-actions для переноса даты существующей активной задачи;
* ответы Mind Hub стали подробнее при создании задач: пользователь видит, какая задача создана и с какими атрибутами;
* Mind Hub теперь получает контекст текущей энергии пользователя и должен учитывать её при советах `с чего начать`;
* добавлена graceful-логика для недоступности AI provider/proxy;
* добавлен hardening для misconfigured AI provider/proxy: при недоступном AI backend больше не создает fallback-задачи из коротких сообщений вроде приветствия, а возвращает безопасный ответ о недоступности ИИ;
* сохранена нормализация дат для задач, созданных через AI.

### AI limits и тарифы

* добавлены тарифные лимиты AI-запросов:
  * demo access: 3 запроса в день;
  * Start: 10 запросов в день;
  * Focus: 100 запросов в день;
  * Forever: 100 запросов в день;
* frontend показывает оставшиеся AI-запросы;
* backend enforcement подключен к текущему тарифу пользователя;
* Focus после оплаты получает увеличенный лимит AI-запросов;
* Forever активируется бесплатно для авторизованного пользователя без YooKassa checkout;
* при клике на Forever гость отправляется на login/register и после входа возвращается в flow активации;
* Start больше не отображается как текущий тариф, если активен Focus или Forever;
* при активном Forever оформление Focus недоступно;
* нижняя информационная плашка на `/pricing` удалена, чтобы страница тарифов была компактнее.

### Payments и billing operations

* Focus использует существующий YooKassa payment-flow:
  * create-payment endpoint;
  * redirect confirmation URL;
  * webhook verification;
  * локальную запись `Payment`;
  * активацию тарифа на 30 дней.
* Forever не создает платеж и не пишет запись в `Payment`;
* Forever устанавливает `User.plan = "forever"`, `subscriptionStatus = "active"`, `planExpiresAt = null`;

### Backend AI refactor

* `ai.routes.js` разбит на сервисные модули;
* добавлен общий Prisma client в `backend/lib/prisma.js`;
* вынесены AI provider calls, Mind Hub parser, Mind Hub service, AI limits и AI utils;
* маршруты стали тоньше и проще для дальнейшего развития AI-функций.

## Известные ограничения / что дальше

* новые task-поля вроде `description`, `time`, `recurrence`, `source` не добавлялись, потому что требуют отдельного backend/DB-плана;
* AI-кнопка в task modal пока является placeholder;
* часть метрик прогресса использует текущие поля задач без отдельной event-history модели.
