# Запуск и размещение Glowy

## Текущее размещение

Приложение доступно на главном домене `glowy-ai.ru`:

- Vercel обслуживает клиентскую часть и перенаправляет запросы `/api` к серверу.
- Render запускает серверную часть на Node.js и Express.
- Neon хранит данные PostgreSQL.

Перенос с Timeweb выполнен. Это не означает восстановление прежней базы:
подтверждённой резервной копии Timeweb нет. Рабочие значения переменных окружения
хранятся в настройках сервисов, а не в репозитории.

## Гостевой режим

Кнопка «Открыть демо без регистрации» открывает задачи, подзадачи, заметки,
привычки, прогресс, аналитику без AI, аватар и обычные настройки.
Заметки поддерживают поиск, архивирование, восстановление, удаление и связи с задачами.
Кнопка «Настроить план» убрана; блоки дня, энергии и следующего шага сохранены.

Гостевой чат доступен при заданном на сервере `GUEST_AI_PROVIDER` со значением
`deepseek` или `gigachat`. Выбирайте провайдера с условиями, подходящими для
публичного демо, и храните его ключ только на сервере. Чат передаёт только новое
сообщение и режим. История, задачи и заметки в запрос не входят. Подтверждённый
черновик сохраняется в браузере. Голосовой ввод и отдельные ИИ-инструменты
для подзадач и заметок доступны только в аккаунте.

Гостевой маршрут допускает 5 попыток за 24 часа на IP или IPv6-подсеть и
до 50 попыток на серверный процесс за 24 часа. Счётчики хранятся в памяти
и сбрасываются при перезапуске. Тариф Start включает 5 запросов за 24 часа,
Focus и Forever — по 30 запросов за 24 часа.
Раздел ИИ-отчётов скрыт в аналитике. Для сборки с отчётами можно задать
`VITE_ANALYTICS_AI_REPORT_ENABLED=true`.
Регистрация, платежи, привязка Telegram и облачная синхронизация остаются закрыты.
Демо не получает серверные права аккаунта или тарифа.

Заметки, привычки, отметки, награды, спасательные круги и аватар хранятся
в IndexedDB `glowy-demo`. Задачи и опыт используют отдельное гостевое хранилище
`localStorage`; обычные настройки сохраняются в браузере.
Переход в аккаунт не загружает гостевые данные на сервер.

Это не резервная копия: очистка данных сайта, другой браузер или приватный режим
могут удалить записи. Если хранилище недоступно или повреждено, приложение сообщает
об ошибке, а не показывает ложное подтверждение сохранения.

## Сборка клиентской части

На Vercel используется корень репозитория:

```sh
npm ci
npm run build
```

Готовые файлы находятся в `dist/`. Переменные `VITE_*` доступны браузеру:
не передавайте через них пароли, токены и ключи провайдеров.

В `vercel.json` запросы `/api` перенаправляются на HTTPS-адрес серверной части.
При смене сервиса Render нужно обновить этот адрес и заново собрать клиентскую часть.
Основной домен привязан к рабочему окружению Vercel; предварительная сборка на
`dev.glowy-ai.ru` его не заменяет.

## Сборка серверной части

На Render поле Root Directory оставляется пустым: сервер использует
общий пакет `packages/contracts` из корня репозитория.

```sh
npm ci
npm --prefix backend ci
npm run build:backend
```

Команда запуска:

```sh
npm --prefix backend run start:prod
```

Сервис передаёт `PORT`. Адрес проверки состояния — `/api/health`.
Шаблон `render.yaml` использует ветку `master` и выключенное автоматическое
развёртывание. Применение шаблона не требуется для уже настроенного сервиса.
Не создавайте второй сервис без необходимости.

Проверки исходных файлов и HTTP-маршрутов используют обычные документы
`docs/backend-source-inventory.md` и `docs/api-endpoints.md`.
Исторические планы разработки для сборки и тестов не нужны.

## База и переменные окружения

Сервер использует подключение к Neon с проверкой TLS-сертификата.
Для удалённой базы нельзя включать `DATABASE_TLS_MODE=local` или отключать проверку
сертификата. Учётные данные базы не передаются клиентской части.

На сервере нужны `DATABASE_URL`, сильный `JWT_SECRET`, `NODE_ENV=production`
и точные HTTPS-адреса разрешённых сайтов в `CORS_ORIGINS`.
`TRUST_PROXY_HOPS` выбирается по фактической цепочке прокси.
Платежи и регистрацию оставляйте выключенными через `PAYMENTS_ENABLED=false`
и `REGISTRATION_ENABLED=false`; на клиенте —
`VITE_REGISTRATION_ENABLED=false`.

Миграции выполняются только для отдельно согласованной базы с проверенной
резервной копией. Не добавляйте их автоматически в каждую сборку или запуск.
Для новой согласованной базы используется:

```sh
npm --prefix backend run migrate:deploy
```

Не запускайте начальное заполнение и не создавайте тестовые аккаунты, задачи
или платежи в рабочей базе. Тесты HTTP используют изолированные зависимости.
Если найдётся копия прежней базы, не импортируйте её без отдельной проверки
состава данных и совместимости схемы.

Яндекс Метрика и аналитический баннер удалены.
Технические cookie авторизации сохраняются.

## Ограничения и проверки после обновления

Бесплатные сервисы могут засыпать; первый запрос после простоя может выполняться
дольше. Фоновая обработка Telegram во время сна не гарантируется.
До отдельной настройки её размещения оставляйте `TELEGRAM_WORKER_ENABLED=false`.
Не используйте искусственные запросы для обхода ограничений тарифа.

После обновления проверьте главный домен, `/api/health`, гостевой режим,
отказ регистрации и оплаты, CSP и работу cookie. Не создавайте тестовые
записи в рабочей базе без разрешения.

Изменения сначала проверяются локально и в CI. Отправка в Git, запуск сборки,
переключение DNS и изменение настроек хостинга — разные действия.
Не выполняйте ручное развёртывание или перезапуск без согласования.

Перед изменением окружения сохраните прежние настройки приватно.
Возврат предыдущей сборки не откатывает миграции и данные.
