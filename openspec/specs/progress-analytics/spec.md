# Progress and Analytics Specification

## Purpose

Определяет честный личный прогресс Glowy: XP, уровни, стрики, привычки, достижения, периодическую
аналитику и premium AI-выводы.

## Requirements

### Requirement: Обзор прогресса

Glowy SHALL возвращать текущие XP и level, порог следующего уровня, task streak, месячный календарь,
спасательные круги, привычки, достижения и entitlement-флаг только для текущего аккаунта.

#### Scenario: Загрузка выбранного месяца
- **WHEN** пользователь передаёт today и месяц не позднее месяца today
- **THEN** backend строит account-scoped обзор и календарь этого месяца

### Requirement: Согласованное клиентское состояние прогресса

Frontend SHALL хранить загруженный progress overview отдельно для каждого аккаунта, локальной
даты и выбранного месяца, MUST NOT показывать или применять ответ предыдущего аккаунта и SHALL
согласовывать подтверждённые мутации привычек и спасательного круга с серверным состоянием.

#### Scenario: Повторное открытие свежего обзора
- **WHEN** текущий пользователь повторно открывает тот же месяц до истечения freshness-периода
- **THEN** frontend показывает сохранённый overview без лишнего блокирующего запроса

#### Scenario: Смена выбранного месяца
- **WHEN** пользователь выбирает другой месяц прогресса
- **THEN** frontend запрашивает данные для новых параметров и не применяет поздний ответ предыдущего месяца

#### Scenario: Смена аккаунта во время запроса
- **WHEN** сессия меняется до завершения загрузки progress overview
- **THEN** frontend отменяет или игнорирует прежний запрос и не показывает его данные новой сессии

#### Scenario: Успешное изменение привычки
- **WHEN** backend подтверждает создание, изменение, отметку, архивирование, восстановление или удаление привычки
- **THEN** frontend сохраняет отзывчивое состояние и приводит overview к подтверждённому сервером результату

#### Scenario: Ошибка изменения привычки
- **WHEN** запрос изменения привычки завершается ошибкой
- **THEN** frontend откатывает неподтверждённое состояние, показывает спокойную ошибку и позволяет повторить действие

#### Scenario: Повтор загрузки после ошибки
- **WHEN** загрузка overview завершилась ошибкой и пользователь выбирает «Повторить»
- **THEN** frontend выполняет новый запрос без перезагрузки страницы и показывает полученные данные

### Requirement: Task streak и спасательный круг

Task streak SHALL основываться на локальных датах завершённых задач. Спасательный круг SHALL
защищать только вчерашний подходящий разрыв, не дублироваться и использоваться не более трёх раз
за календарный месяц.

#### Scenario: Допустимое спасение
- **WHEN** вчерашний день является единственным подходящим разрывом и месячный лимит не исчерпан
- **THEN** backend создаёт уникальную защиту и возвращает пересчитанный overview

#### Scenario: Недопустимая дата
- **WHEN** пользователь пытается защитить не вчерашний или не соединяющий текущий streak день
- **THEN** backend отклоняет операцию без изменения прогресса

### Requirement: Привычки

Пользователь SHALL создавать, переименовывать, архивировать, восстанавливать и удалять свои привычки,
а также идемпотентно отмечать и снимать выполнение по календарной дате.

#### Scenario: Повторная отметка дня
- **WHEN** пользователь повторно отмечает ту же привычку в ту же дату
- **THEN** backend сохраняет одну HabitCheck и возвращает неизменённую корректную серию

### Requirement: Достижения

Glowy SHALL выдавать достижение не более одного раза на account и пересчитывать доступные достижения
из завершённых задач, task streak и привычек при загрузке progress overview.

#### Scenario: Повторная загрузка прогресса
- **WHEN** условия достижения уже были выполнены и achievement сохранён
- **THEN** повторная сверка не создаёт дубликат

### Requirement: Аналитика периода

Пользователь SHALL получать account-scoped агрегаты за неделю или месяц относительно anchor-даты;
переключение периода или аккаунта MUST NOT показывать устаревший ответ предыдущего запроса.

#### Scenario: Период без активности
- **WHEN** за выбранный период нет завершённых задач
- **THEN** backend возвращает корректный пустой snapshot с `hasActivity=false`

### Requirement: Premium AI-вывод

AI-вывод по аналитике SHALL быть доступен только активному Focus или Forever, требовать минимум одну
завершённую задачу и атомарно резервировать 5 запросов для недели либо 10 для месяца.

#### Scenario: Недостаточный entitlement
- **WHEN** пользователь Start запрашивает AI-вывод
- **THEN** backend возвращает `403` до обращения к AI-провайдеру

#### Scenario: Ошибка AI
- **WHEN** провайдер не формирует вывод
- **THEN** backend освобождает резерв и возвращает спокойное сообщение о повторе
