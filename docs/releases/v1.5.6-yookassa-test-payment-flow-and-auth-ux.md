# Релиз v1.5.6 - YooKassa Test Payment Flow & Auth UX

## Обзор
Этот релиз продолжает подготовку Glowy к коммерческому запуску v2.0.0. Основное внимание уделено первому тестовому payment flow для тарифа Focus через ЮKassa, базовым billing-endpoints на backend и небольшим улучшениям UX авторизации.

Production-оплата пока не считается включенной. Перед master/prod-деплоем публичный вход в оплату должен оставаться закрытым feature flag, заглушкой или другим безопасным механизмом до отдельного решения о коммерческом запуске.

## Изменения

### Auth UX fixes
- Улучшена работа autocomplete для паролей:
  - вход использует `current-password`;
  - регистрация использует `new-password`.
- На регистрации уточнена подсказка: «Пароль (минимум 8 символов)».
- Добавлена клиентская проверка пароля короче 8 символов с понятным сообщением.
- Сохранены кнопки показа/скрытия пароля (eye toggle).

### Backend payment foundation
- Добавлен protected endpoint `GET /api/payments/current-plan`.
- Добавлен protected endpoint `POST /api/payments/focus/create`.
- Цена и тариф Focus задаются на backend, frontend не передает сумму или plan.
- Для создания платежа используется ЮKassa Basic Auth.
- Добавлен `Idempotence-Key` для запроса создания платежа.
- После создания платежа сохраняется запись `Payment`.
- Frontend получает только безопасные данные:
  - `paymentId`;
  - `confirmationUrl`.

### YooKassa webhook
- Добавлен public endpoint `POST /api/payments/yookassa/webhook`.
- Webhook расположен до `authMiddleware`, поэтому не требует пользовательской авторизации.
- Добавлено точечное CSRF-исключение только для `POST /api/payments/yookassa/webhook`.
- Обрабатываются события:
  - `payment.succeeded`;
  - `payment.canceled`.
- Перед изменением данных платеж перепроверяется через API ЮKassa.
- При успешной оплате обновляются `Payment` и `User`.
- Тариф Focus активируется на 30 дней.
- Webhook не возвращает наружу raw YooKassa response и не логирует секреты.

### Frontend payment work
- Создан `src/api/PaymentApi.ts`.
- Начата интеграция кнопки Focus на `/pricing`.
- Кнопка вызывает `POST /api/payments/focus/create`.
- При получении `confirmationUrl` пользователь перенаправляется на страницу оплаты ЮKassa.
- Добавлен loading state и базовая обработка ошибки.
- Перед production-запуском payment entry-point на `/pricing` должен быть закрыт или переведен под feature flag, если оплата еще не запускается публично.

### Production safety
- Backend payment code подготовлен для тестового flow, но production-оплата не должна быть публично доступна до коммерческого запуска.
- На production пользователи пока не должны видеть активную оплату, если нет отдельного решения о запуске Focus.
- Перед включением оплаты нужно отдельно проверить env, webhook URL, тестовый/боевой режим ЮKassa, юридические страницы и поведение подписки после оплаты.

## Известные ограничения / что дальше
- Frontend payment flow находится в статусе in progress.
- Success/cancel pages для оплаты еще требуют финальной проверки/доработки, если они не завершены в отдельном diff.
- Production payment entry-point должен быть выключен до коммерческого запуска.
- Для v2.0.0 нужно завершить управление подпиской, UX оплаты, billing states и QA коммерческого сценария.
