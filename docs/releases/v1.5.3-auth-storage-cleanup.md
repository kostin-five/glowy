# Релиз v1.5.3 - Auth & Storage Cleanup

## Обзор
Этот релиз направлен на очистку и укрепление слоя авторизации и хранения данных перед коммерческим запуском v2.0.0. Основное внимание уделено исправлению предупреждений rate-limit, восстановлению сессии через бэкенд и гигиене локального хранилища.

## Изменения

### Backend
- **Rate-limit IP Key**: Исправлено использование `req.ip` в `keyGenerator` с помощью `ipKeyGenerator` для устранения предупреждения `ERR_ERL_KEY_GEN_IPV6`. 
- **Auth Profile & Session Restore**: Добавлен эндпоинт `/api/auth/me`, который теперь используется фронтендом как единственный источник истины для восстановления сессии при загрузке приложения. Проверка сессии выполняется в фоновом режиме (silent check) и не мешает просмотру публичных страниц.
- **Security**: 
  - Bcrypt cost для новых регистраций поднят до `10`.
  - Сообщение о длине пароля уточнено: «Пароль должен быть не короче 8 символов».
  - Исправлено использование `ipKeyGenerator(req.ip)` для корректного определения IP-адреса в rate-limit.
- **Auth Middleware**: Подтверждена поддержка HttpOnly cookie. Bearer fallback оставлен временно для совместимости (запланирован аудит).

### Frontend
- **Session Restore**: Реализован вызов `/api/auth/me` при инициализации. Авторизация больше не восстанавливается «вслепую» только по данным из localStorage. Публичные страницы (лендинг, регистрация) теперь корректно работают для неавторизованных пользователей без лишних редиректов.
- **Storage Hygiene**: При выходе из системы (`logout`) теперь принудительно очищаются:
  - Состояние авторизации (`auth-storage`).
  - Кэш задач (`glowy-tasks`).
  - Прогресс пользователя и энергия.
  - Устаревшие токены.
- **Demo Mode**: Сохранено разделение демо-режима и авторизованной сессии. Демо-данные очищаются при выходе.

## Проверка
- [x] Регистрация с паролем >= 8 символов (bcrypt cost 10).
- [x] Восстановление сессии через `/api/auth/me` после обновления страницы.
- [x] Выход с полной очисткой localStorage и кэша задач.
- [x] Отсутствие предупреждений `ERR_ERL_KEY_GEN_IPV6` в логах.
- [x] `/api/auth/me` возвращает 401 без валидной cookie.

## Примечания
- **IndexedDB**: Внедрение IndexedDB не входит в v1.5.3 и запланировано для v2.7.0 Offline-first Foundation.
- **AI Reliability**: Исправление ошибок Gemini запланировано на версию v1.5.4.
- **Legacy Hashes**: Старые пароли (cost 7) продолжают работать. Перехеширование при входе запланировано на будущие версии.
