# Research: Мобильная навигация заметок

## Решение 1: responsive rendering вместо отдельного mobile route

Использовать существующие `/notes` и `/notes/:noteId?`, а mobile-режим выводить из URL и одного локального флага новой заметки вместе с responsive-классами. Это сохраняет deep links и не создаёт параллельную страницу или store.

## Решение 2: маршрут остаётся источником выбранной сохранённой заметки

`/notes/:id` открывает редактор через производное `Boolean(noteId)`. Переход к `/notes` закрывает его на mobile. Для нового черновика без id используется только `newNoteOpen`; после первого save существующий flow заменяет URL на `/notes/:id`.

## Решение 3: возврат использует существующий save flow

Функция сохранения возвращает `boolean`: `true` только если данные уже безопасны или API успешно завершился. Мобильный back закрывает редактор лишь при `true`; ошибка сохраняет текст и поверхность редактора.

## Решение 4: CSS breakpoint без JavaScript media listener

Обе поверхности остаются в DOM и переключаются responsive-классами `hidden/flex` и `lg:flex`. Это избегает hydration/media listener сложности, а состояние определяет только то, какая поверхность основная на mobile.

## Отклонённые варианты

- Отдельный `/notes/mobile` — ломает единый URL contract и дублирует route composition.
- Modal/editor drawer — ухудшает deep links и создаёт проблемы с длинным текстом и клавиатурой.
- Закрытие до завершения save — создаёт видимую потерю данных при сетевой ошибке.
- Новый Zustand store для навигации — избыточен для локального page state.
