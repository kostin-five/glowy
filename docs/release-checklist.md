# Проверки перед выпуском демонстрационной версии

1. Проверить примеры переменных окружения, отсутствие секретов и персональных данных в текущих файлах и истории.
2. Проверить типы, стиль кода, общие контракты, тесты клиентской и серверной частей, сборки и Playwright.
3. Проверить зависимости; отдельно указать уязвимости рабочих библиотек и инструментов разработки.
4. Применять миграции только после согласования новой целевой базы; не восстанавливать данные без backup.
5. Локально проверить авторизацию, выход и повторное использование токена, права владельца, задачи, работу без интернета, AI-квоту и Telegram.
   На размещённом приложении проверить состояние сервера, гостевой режим, отказ регистрации и оплаты без записи тестовых данных.
   Непроверенные сценарии аккаунта указать отдельно; начальное заполнение базы не запускать.
6. Проверить CSP, cookie и первый запуск после простоя на фактическом хостинге.
7. Проверить отчёты сборок, обсуждения, запросы на слияние, релизы и вложения GitHub вручную.
8. Перед переписыванием истории создать резервную копию Git; принудительная отправка и открытие публичного доступа требуют отдельного разрешения.
9. При переиспользовании Render dev сначала выключить Auto-Deploy, затем проверить
   новую базу, готовый `master`, команды сборки и серверные переменные окружения. После разрешённого
   ручного развёртывания проверить основные сценарии; только затем включать After CI Checks Pass.
10. Проверить блокирующую CSP и отсутствие Метрики даже при старом согласии на аналитические cookie.
